# Data Model: HTTP Request Authentication (auth)

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Research**: [research.md](research.md)

The module stores nothing of its own beyond the developer's store. Its "data" are:

- the values that flow through a request;
- the records it writes to the store;
- the records the developer keeps in their own database, which the module reads through lookups.

The Go signatures are in [contracts/public-api.md](contracts/public-api.md). The store layout is
in [contracts/store.md](contracts/store.md).

## 1. Request-scoped values

### Principal

| Field | Type | Rules |
|-------|------|-------|
| `Subject` | string | Non-empty (FR-012). An empty subject from a method is a contract error, answered with 500 (FR-013). |
| `Methods` | []string | RFC 8176 values, in the order they were added, without duplicates. It may be empty (API keys, tokens without `amr`). |
| `Extra` | any | Data specific to the method that produced the principal. Only `jwt` sets it (R-03). It is never persisted. |

Methods per producer:

| Producer | `Methods` |
|----------|-----------|
| `password.Checker.Check`, `basic` | `["pwd"]` |
| `totp.Verifier.Verify` | pending methods + `otp`, `mfa`, so `["pwd","otp","mfa"]` |
| `recovery.Verifier.Verify` | pending methods + `mfa`, so `["pwd","mfa"]` |
| `session` | the methods recorded at issuance |
| `apikey` | `[]`, empty |
| `jwt` | the `amr` claim, or empty |

### Outcome of an authentication

Every call to `Authenticate` has exactly one outcome (FR-011). It is classified in this order
(R-04):

| Outcome | Recognized by | Combination (`Any`) | Middleware |
|---------|---------------|---------------------|------------|
| principal | non-nil principal, nil error | stop, success | next handler |
| no credentials | `errors.Is(err, ErrNoCredentials)` | try the next method | 401, or pass anonymously |
| too many attempts | `errors.Is(err, ErrTooManyAttempts)` | stop | 429 |
| invalid credentials | `errors.Is(err, ErrInvalidCredentials)` | stop | 401 |
| failure | any other error, or a contract violation | stop | 500 |

### Rejection

| Field | Type | Values |
|-------|------|--------|
| `Status` | int | 401, 403, 429 or 500 |
| `Err` | error | Matches one of `ErrNoCredentials`, `ErrInvalidCredentials`, `ErrTooManyAttempts` or `ErrInsufficientMethods`, or is the failure, for 500 |

### Middleware state, in the request context, unexported

| Field | Meaning |
|-------|---------|
| principal | the principal, or nil in anonymous mode |
| decider | the leaf method that decided the request (R-04), used for step-up challenges |
| challenges | the plain challenges of all leaves, deduplicated (R-05) |
| reject | the configured `RejectFunc` |

`FromContext` reports `(nil, false)` when the state is absent or holds no principal.
`RequireMethods` answers 500 when the state is absent (R-07).

## 2. Store records

The keys are `auth:<kind>:<digest>` (R-09). TTLs are always greater than 0.

| Kind | Value | TTL | Writer | Readers |
|------|-------|-----|--------|---------|
| `session` | session record | `min(rw + idle, exp) − now`, set at every write | `session` | `session` |
| `pending` | pending record | pending lifetime | `session` | `session` |
| `pending-attempts` | counter | pending lifetime, from the first attempt | `session` (`Pending.Attempt`) | none (`Incr` only) |
| `password-attempts` | counter | attempt window, from the first attempt | `password` | none (`Incr` only) |
| `totp-used` (`…:<step>`) | counter | 4 steps (2 min) | `totp` | none (`Incr` only) |
| `recovery-used` | counter | 10 min | `recovery` | none (`Incr` only) |

### Session record (JSON, `v` = 1)

| Field | Type | Meaning |
|-------|------|---------|
| `v` | int | format version; any other value is an error |
| `sub` | string | principal subject |
| `amr` | []string | principal methods |
| `iat` | int64 | issuance, Unix seconds |
| `exp` | int64 | absolute expiry, `iat + lifetime` |
| `rw` | int64 | time of the last write, for renewal |

### Pending record (JSON, `v` = 1)

| Field | Type | Meaning |
|-------|------|---------|
| `v` | int | format version |
| `sub` | string | subject of the first factor |
| `amr` | []string | methods of the first factor, `["pwd"]` |
| `iat` | int64 | issuance |

## 3. Records in the developer's database (read through lookups)

| Record | Fields the module needs | Read by | "Not found" means |
|--------|-------------------------|---------|-------------------|
| `password.Account` | `Subject`, `Hash` (PHC argon2id or bcrypt) | `password.LookupFunc(ctx, username)` | the account does not exist, so the dummy hash is verified (FR-026) |
| TOTP secret | `[]byte`, 20 bytes when generated by the module | `totp.LookupFunc(ctx, subject)` | not enrolled (FR-043) |
| Recovery code hashes | `[]string`, lowercase SHA-256 hex of the unused codes | `recovery.LookupFunc(ctx, subject)` | no codes, so every code is invalid |
| `apikey.Account` | `Subject`, `Hash` (32 bytes), `ExpiresAt` (zero means no expiry) | `apikey.LookupFunc(ctx, id)` | deleted or never existed, so invalid (FR-057) |

The developer also writes:

- the new password hash passed to `RehashFunc`;
- the confirmed TOTP secret;
- the recovery code hashes, from `Codes.Hashes()`, and their consumption through `ConsumeFunc`;
- the API key's `Stored` (`ID`, `Hash`), with its owner and an optional expiry.

## 4. Password hashes

### PHC argon2id

`$argon2id$v=19$m=<KiB>,t=<iterations>,p=<parallelism>$<salt b64>$<key b64>`, with unpadded
standard base64.

| Parameter | Default | Floor when configured | Accepted when stored |
|-----------|---------|------------------------|----------------------|
| memory `m` (KiB) | 19,456 | ≥ 7,168, and m × t ≥ 35,840 | 1 to 2,097,152 |
| iterations `t` | 2 | ≥ 1 (and the product) | 1 to 100 |
| parallelism `p` | 1 | 1 to 64 | 1 to 64 |
| salt | 16 bytes | 16 bytes | 8 to 64 bytes |
| key | 32 bytes | 32 bytes | 16 to 64 bytes |
| version `v` | 19 | 19 | 19 only |

A hash is **outdated** when its algorithm is bcrypt, or when any parameter, the salt length or
the key length differs from the checker's current values. An outdated hash is rehashed after a
successful check when `WithRehash` is set (FR-029).

### bcrypt

Prefixes `$2a$`, `$2b$` and `$2y$` are accepted, with the cost the bcrypt package accepts. A
password over 72 bytes never matches (FR-028).

### Password length

A password must have between 1 byte and the maximum length in bytes, which defaults to 1,024.
Outside these bounds, `Hash` returns `ErrEmpty` or `ErrTooLong`, and `Check` returns
`ErrInvalidCredentials` before any work.

## 5. Session lifecycle

```text
                 Issue
   (none) ───────────────────▶ ACTIVE ──── Revoke, or a new Issue on the same request ───▶ DELETED
                                │  ▲
             request with       │  │ renewal write
             now − rw ≥ idle/4  └──┘ (rw = now, TTL = min(now + idle, exp) − now)
                                │
                                ├── now ≥ rw + idle  (no renewal in time) ───────────────▶ EXPIRED (idle)
                                └── now ≥ exp ───────────────────────────────────────────▶ EXPIRED (absolute)
```

- DELETED and EXPIRED sessions, and cookies that do not decode, produce `ErrNoCredentials`
  (FR-034).
- A request in ACTIVE costs one `Get`, plus one `Set` when the renewal is due (SC-006).

## 6. Pending login lifecycle

```text
  IssuePending           attempt n ≤ 5, verify ok                 Issue
 ─────────────▶ OPEN ──────────────────────────────▶ VERIFIED ───────────▶ DELETED (session issued)
                 │  │
                 │  └─ attempt n < 5, verify fails ──▶ OPEN (n recorded)
                 │
                 ├─ attempt n = 5, verify fails ──▶ CANCELLED (deleted)
                 │                                  returns ErrTooManyAttempts wrapping ErrInvalidCredentials
                 ├─ attempt n > 5 (parallel) ─────▶ CANCELLED, returns ErrTooManyAttempts
                 └─ pending lifetime elapsed ─────▶ EXPIRED
```

- `Pending(r)` returns `ErrNoCredentials` in CANCELLED, EXPIRED and DELETED (FR-039).
- `Attempt` counts before calling `verify`. A store failure while counting is not counted, and
  a failure inside `verify` stays counted (FR-045, R-12).
- `IssuePending` on a request that already carries a pending login deletes the old one.

## 7. Second factor

### TOTP

| Item | Value |
|------|-------|
| Secret | 20 bytes (160 bits) from `crypto/rand` |
| Algorithm | HMAC-SHA-1, 6 digits, 30-second step from the Unix epoch |
| Accepted steps | t − 1, t, t + 1 |
| Replay | `Incr(totp-used:<digest(subject)>:<step>)`; a value > 1 is a replay |
| URI | `otpauth://totp/<issuer>:<account>?secret=<BASE32>&issuer=<issuer>&algorithm=SHA1&digits=6&period=30` |

Enrollment lifecycle, held by the developer:

```text
 NewEnrollment ──▶ CANDIDATE (developer keeps the secret, not active) ── Confirm ok ──▶ developer stores it as active ──▶ ENROLLED
                        │
                        └── Confirm fails ──▶ CANDIDATE (retry, or discard)
```

### Recovery codes

| Item | Value |
|------|-------|
| Count | `n` in 1 to 100; `DefaultCount` = 10 |
| Code | 10 random bytes as 16 Crockford base32 characters, shown as `xxxx-xxxx-xxxx-xxxx` |
| Normalized input | lower-cased, spaces and hyphens removed, `i`/`l` → `1`, `o` → `0`; exactly 16 alphabet characters |
| Hash | lowercase hex SHA-256 of the 16-character normalized code |

Lifecycle: GENERATED (shown once) → STORED (the developer keeps the hashes) → CONSUMED (by
`ConsumeFunc`; the lookup no longer returns the hash). Regenerating replaces the set in the
developer's database.

## 8. API keys

```text
<prefix> "_" <id> "_" <secret>
   │          │         └── 32 random bytes → 52 Crockford base32 characters (256 bits)
   │          └── 10 random bytes → 16 Crockford base32 characters (public, used by the lookup)
   └── 1–32 ASCII letters and digits, starting with a letter (validated by New)
```

| Type | Fields |
|------|--------|
| `Key` | the full key, a `string`; `LogValue` returns `[REDACTED]` |
| `Stored` | `ID` (16 characters), `Hash` (SHA-256 of the 32 secret bytes) |
| `Account` | `Subject` (owner), `Hash`, `ExpiresAt` |

Lifecycle: GENERATED (shown once) → STORED by the developer → ACTIVE → EXPIRED (`ExpiresAt` has
passed) or DELETED (the lookup reports `ErrNotFound`). Both end states produce
`ErrInvalidCredentials`.

## 9. Tokens and key sets

### Bound key

| Field | Meaning |
|-------|---------|
| kid | key identifier, possibly empty for static keys |
| alg | exactly one of RS256, PS256, ES256, EdDSA, HS256 (FR-060) |
| key | `*rsa.PublicKey` (≥ 2,048 bits), `*ecdsa.PublicKey` (P-256), `ed25519.PublicKey` or `[]byte` (≥ 32 bytes, static HS256 only) |

Algorithm of keys from a key set that declare none: RS256 for RSA, ES256 for P-256 and EdDSA for
Ed25519.

### Claims mapping

| Claim | Rule | Principal |
|-------|------|-----------|
| `exp` | required; checked with the leeway | none |
| `nbf`, `iat` | checked with the leeway when present | none |
| `iss` | equal to the configured issuer | none |
| `aud` | contains the configured audience | none |
| `sub` | required, non-empty | `Subject` |
| `amr` | absent, or a list of strings | `Methods` |
| all of the above and the rest | none | `Extra`, read through `jwt.Claims(p)` |

### Key set cache (remote keys only)

```text
 EMPTY ── first verification ──▶ DOWNLOADING ── ok ──▶ FRESH (until now + clamp(max-age, 1 min, 24 h); 1 h by default)
                                     │                   │
                                     └── fails ──▶ FAILED (no keys: 500 until the next allowed download)
 FRESH ── lifetime elapsed ──▶ STALE ── next verification, download allowed ──▶ DOWNLOADING
 FRESH/STALE ── unknown kid, download allowed ──▶ DOWNLOADING
 DOWNLOADING (keys present) ── fails ──▶ previous keys kept, lastErr recorded
```

- "Download allowed" means the refresh interval has passed since the last attempt, whether it
  succeeded or failed (default 30 s).
- Concurrent verifications that need a download share the one in flight.
- An unknown `kid` produces:
  - `ErrInvalidCredentials` when the last download succeeded;
  - an error answered with 500 when the last download failed (FR-064, R-18).

## 10. Defaults and limits

| Setting | Default | Configurable with | Validation |
|---------|---------|-------------------|------------|
| argon2id parameters | 19 MiB, t=2, p=1 | `password.WithParams` | floor and bounds of §4 |
| Maximum password length | 1,024 bytes | `password.WithMaxLength` | 256 to 4,096 bytes (at least 64 characters in any script, FR-028) |
| Attempt limit | off; when on, 10 per 15 min | `password.WithAttemptLimit` | `Store` not nil; `Max` ≥ 0 and `Window` ≥ 0, where 0 selects the default |
| Session lifetime | 8 h | `session.WithLifetime` | > 0 |
| Idle timeout | 30 min | `session.WithIdleTimeout` | > 0 and ≤ lifetime |
| Renewal interval | idle / 4 | none | none |
| Pending lifetime | 5 min | `session.WithPendingLifetime` | > 0 and ≤ 1 h |
| Second-factor attempts | 5 per pending login | none | none |
| Cookie base name | `session` | `session.WithCookieName` | HTTP token, at most 64 bytes |
| TOTP replay TTL | 2 min | none | none |
| Recovery guard TTL | 10 min | none | none |
| Basic realm | `restricted` | `basic.WithRealm` | 1 to 128 printable ASCII characters |
| API key header | `Authorization: Bearer` | `apikey.WithHeader` | valid header name, not `Authorization` |
| Clock leeway | 1 min | `jwt.WithLeeway` | 0 to 5 min |
| Key set refresh interval | 30 s | `jwt.WithRefreshInterval` | 1 s to 1 h |
| Key set lifetime | `max-age`, clamped to 1 min to 24 h; 1 h without it | none | none |
| Key set size | 1 MiB | none | none |
| Key set download timeout | 10 s, fixed on the download context | none; a client timeout set with `jwt.WithHTTPClient` applies only when shorter | client not nil |
